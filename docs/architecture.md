# Architecture

## Stack

| Layer | Choice | Why |
|---|---|---|
| Language | TypeScript end to end | One language for UI, API, tests and scripts |
| Framework | Next.js 15.5 App Router | Server Components for content pages, Route Handlers for the API |
| Styling | Tailwind CSS + generated design tokens | Tokens come from `ui-ux-pro-max`, not hand-picked |
| Validation | Zod | One schema shared by website query strings and API |
| Database | PostgreSQL via Supabase | Transactions across availability, booking and payment |
| ORM | Prisma | Type-safe queries, migrations, drift detection |
| Auth | Supabase Auth (planned) | Session in middleware, roles in `app_metadata` |
| Deployment | Vercel (planned) | Preview environments per branch |
| Tests | Vitest + Playwright | Unit/integration in Vitest, journeys in Playwright |

## The storage seam

The destination repository (`src/lib/destinations/repository.ts`) is the only module that
reads destination data. Today it serves a static curated dataset; the query, filter,
facet and pagination semantics are written exactly as the Postgres implementation will
behave.

That seam means:

- The website and the public API are built once, against one contract.
- Swapping static data for Postgres touches one module, not the pages.
- Filter behaviour is unit-testable without a database.

Do not import `src/data/destinations.ts` from a page or a route handler. Go through the
repository.

## Request flow

```
Browser
  → Next.js route (page or Route Handler)
    → Zod validation (shared schema)
      → repository (data access)
        → static dataset | PostgreSQL
```

Authorization layers, in order: route guard, Zod input validation, server-side
ownership/membership check, scoped query, Postgres RLS.

## Money and dates

- Money is stored as `amountMinor: Int` plus `currency: Char(3)`. Never floating point.
- Timestamps are `timestamptz`. User-facing local dates are stored as `date` plus a
  timezone, so a booking never silently shifts across a border.

## Tenancy

Each hotel, lodge, guest house, agency or cruise operator is an `Organization`. Every
organisation-scoped table carries `organization_id UUID NOT NULL` included in every
composite index, and Postgres RLS filters on
`current_setting('app.current_tenant_id')`. Cross-tenant admin routes use a separate
database role and never reuse a tenant session.

## Design authority

`design-system/letxnepal/MASTER.md` and `tokens.json` are generated by the
`ui-ux-pro-max` skill and are the single source of visual truth. See
`docs/provenance.md` for the two documented deviations (font and motion) and for the
contrast measurements.

## Security posture

- Security headers (CSP, HSTS, `X-Frame-Options: DENY`, `Referrer-Policy`,
  `Permissions-Policy`) are set centrally in `next.config.ts`.
- Admin-authored HTML is sanitized server-side before storage and rendered from
  sanitized output only.
- The Supabase `service_role` key never appears in client code; any `NEXT_PUBLIC_`
  variable is assumed to reach the browser.
- Roles come from `app_metadata`, which the user cannot edit. `user_metadata` is never
  used for authorization.

## Testing layers

| Layer | Tool | Gate |
|---|---|---|
| Unit and integration | Vitest | `npm test` before every commit |
| Structural accessibility | Vitest source checks | every input labelled, focus visible |
| Token integrity and WCAG contrast | Vitest | `tests/tokens.test.ts` |
| Browser journeys | Playwright | booking flow, CMS |
| Types and lint | `tsc`, ESLint | 0 errors |
| Build | `next build` | success |
| Security | header assertions, secret grep | no critical findings |

## Commands

```bash
npm run dev          # start the app
npm run build        # production build
npm test             # unit and integration tests
npm run test:e2e     # Playwright journeys
npm run typecheck    # tsc --noEmit
npm run lint         # ESLint
npm run design:query "<query>" -- --design-system   # query the design skill
```

## Environment variables

`.env.local.example` lists every variable. Real `.env*` files are gitignored. Never
commit a key; rotate any key that has appeared in a commit, log or message.
